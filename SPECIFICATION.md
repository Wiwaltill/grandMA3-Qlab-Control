# QLab Control — project specification
## Context and goal
A single lighting operator manually advances grandMA3 song sequences using GO+. No timecode and no dedicated QLab operator. QLab on a Mac plays video cues for an LED wall and additional displays. MA should trigger specific QLab cues without disrupting existing lighting workflow. This is intended to be reused across shows. QLab keeps ownership of media routing, groups, fades and timing.
## V1 architecture
Native grandMA3 Lua plugin + Layout Pool UI + Macro Pool actions + Appearance Pool graphics + namespaced show variables for persistence. Use MA's configured outgoing OSC connection (UDP; QLab typical port 53000). User configures OSC routing manually in V1; setup stores the output index, optional destination metadata, special cue IDs and pool IDs. Do not imply metadata changes actual OSC routing. QLab OSC control permissions must be configured for a trusted isolated show network. Consult https://help.malighting.com/ and https://qlab.app/docs/v5/ for version-specific API details.
Proposed cue command interface: Plugin "QLab Control" "START 101" or "START 101.2" in the sequence CMD column; validate syntax on target MA. Trigger first cue of each song, optionally further video changes on later cues, then idle graphic at end. Ordinary lighting cues need no video command. Cue numbers need not be sequential; matching MA sequence IDs is a useful convention, not a requirement. QLab groups may launch several video outputs. Explicitly program stopping/fading previous groups in QLab; starting another group does not guarantee that old video stops.
## Native layout design
Dark background (#171717), rectangular color-coded buttons, readable high-contrast labels and icons. Top status area: LAST TRIGGERED CUE, cue identifier (optional known name), configured OSC output index and destination if available. No online indicator or progress simulation in V1.
Three columns:
| START (green) | PAUSE (amber) | STOP (red) |
| RESTART (slate) | RESUME (green) | NEXT CUE (slate) |
| PAUSENGRAFIK (blue) | BLACKOUT (near black) | PANIC (red) |
Bottom: SELECT CUE and SETUP (neutral gray).
Start/pause/stop/restart/resume target the selected/current song cue. Distinguish selected cue, last requested cue and last song so special graphics do not destroy the song reference. NEXT CUE is explicitly manual QLab GO, not arithmetic cue ID increment; warn about playhead dependence. Normal automated commands address explicit cue IDs. Panic is workspace-wide and requires confirmation; verify exact QLab behavior. Blackout and idle are configurable QLab cues, not implicit global stops. Restart semantics (stop then start or documented equivalent) must be verified; avoid arbitrary timing assumptions. SELECT CUE accepts string IDs. No automatic audio/video output changes from installation.
## Setup and installation
Setup fields: QLab IP (example only 192.168.10.50), port (53000), MA OSC output index (1), idle cue (900), blackout cue (901), layout ID (200), macro start ID (501), appearance start ID (501). All are editable examples. Preflight ranges and conflicts; fail safely without overwrites. Create native layout, action macros and appearances automatically; use native labels/colors and original icons/assets if supported. Persist configuration in show; verify behavior across save/reload and data pools. Provide explicit install/update/uninstall/test operations and only remove owned objects. Importable XML/Lua and required assets in release ZIP; actual folder structure must match MA export/import behavior.
## Validation
Test command parser, input validation, command construction, state transitions and collision behavior with mocks. Manual integration checklist: onPC import; install in occupied and empty pools; reopen show; test OSC start/stop/pause/resume/restart against QLab; decimal cue numbers; manual GO+ sequence with intermediate video change; multiple outputs; out-of-order songs; disconnected Mac; panic confirmation; repeated installs; safe cleanup. Verify cue/group behavior and exact OSC addresses and argument types. No confirmed playback or delivery claims in V1. Hardware tests are pending; design is not yet implemented.
## V2 (future)
Actual QLab playback state, online/connection monitoring, cue list/name discovery, elapsed/remaining duration and progress. Investigate OSC replies and MA receive capabilities; a Mac bridge may be needed. Do not claim direct reply integration until demonstrated. V2 UI: ONLINE only with fresh evidence, NOW PLAYING, PLAYING/PAUSED, elapsed/total, progress bar, remaining time and transport controls.
